# 图片资源规则

图片服务于讲解，不是必选装饰。默认先问用户是否需要配图；如果用户已经明确要求视觉化产物，再主动选择少量关键节点配图。

## 何时配图

优先给这些节点配图：
- 总览、框架、流程、时间线、架构、对比、清单、风险模型。
- 需要降低认知负担的复杂概念。
- 代码片段、界面流程或结构关系。

短材料可不配图或只配 1-2 张；长材料通常控制在 3-8 张。

## 获取顺序

1. **用户提供图片**：优先复制或引用用户提供的本地资源。
2. **AI 生成图片**：仅在用户需要视觉化且当前可用图片生成工具时使用。
3. **代码转图片**：材料包含代码且适合展示时，使用脚本生成代码截图。
4. **跳过图片**：如果图片只是装饰，直接不配图。

## 存放与引用

推荐把新生成或整理的图片放在：

```text
project/images/
```

在 `window.sourceMarkdown` 中使用短路径引用：

```md
@image images/example.png
```

短路径会解析为 `./project/images/example.png`。

每个节点最多引用 1 张图片。当前播放器只支持一个节点渲染一张图片；如果同一个观点确实需要多张图，拆成多个相邻子节点分别添加 `@image`。

## AI 生成图片

生成图片时：
- 使用中文 prompt，除非用户要求其他语言。
- 保存为 PNG 格式。
- 文件名使用小写英文、数字和连字符，例如 `process-flow.png`。

## 代码转图片

如果要把代码片段变成图片：
1. 先把代码保存成独立文件，例如 `project/codes/example.js`。
2. 再运行：

```bash
python scripts/code-to-image.py <代码文件> [输出路径]
```

脚本依赖：

```bash
pip install pygments pillow
```

输出路径如果是目录，会生成同名 `.png` 文件。
